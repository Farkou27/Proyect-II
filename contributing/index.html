    🤝 Guía de Contribución¶

    ¡Gracias por tu interés en contribuir a Biblioteca C++! Este documento te guía en el proceso.

    🌟 Formas de Contribuir¶

    Tipo Descripción Dificultad
    🐛 Bug Reports Reportar errores en Issues Fácil
    💡 Feature Requests Proponer nuevas funcionalidades Fácil
    📝 Documentación Mejorar docs, traducir, ejemplos Fácil
    🔧 Code Fix bugs, añadir features, refactor Media
    🧪 Tests Aumentar cobertura de tests Media
    🎨 UI/UX Mejorar menú, colores, UX Media

    🚀 Primeros Pasos¶

    1. Fork y Clone¶

    # Fork en GitHub, luego:
git clone https://github.com/TU-USUARIO/biblioteca-cpp.git
cd biblioteca-cpp
git remote add upstream https://github.com/ORIGINAL/biblioteca-cpp.git

    2. Crear Rama¶

    git checkout -b feature/nueva-funcionalidad
# o
git checkout -b fix/correccion-bug
# o
git checkout -b docs/mejora-documentacion

    3. Desarrollar¶

    # Compilar
cd ProyectBiblio
g++ -std=c++17 -Wall -Wextra -g main.cpp Biblioteca.cpp -o biblioteca

# Probar cambios
./biblioteca

    4. Verificar Calidad¶

    # Compilación limpia
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror main.cpp Biblioteca.cpp -o test_build

# Static analysis (opcional)
clang-tidy main.cpp Biblioteca.cpp -- -std=c++17
cppcheck --enable=all --std=c++17 .

# Tests manuales
./biblioteca <<< "2"  # Ver catálogo
./biblioteca <<< $'3\n1984\n4\n1984\n0'  # Préstamo/devolución

    📋 Estándares de Código¶

    Estilo C++¶

    • Estándar: C++17 (mínimo)
    • Formato: clang-format (config incluido)
    • Naming:
    • Clases: PascalCase (Biblioteca, Libro)
    • Métodos/funciones: camelCase (agregarLibro, mostrarCatalogo)
    • Variables: camelCase (catalogo, titulo)
    • Constantes: UPPER_SNAKE_CASE (DIAS_MAXIMO_PRESTAMO)
    • Privados: _suffix opcional (catalogo_)

    Inclusiones¶

    // 1. Sistema/STL
#include <iostream>
#include <memory>
#include <vector>

// 2. Proyecto (orden alfabético)
#include "Biblioteca.h"
#include "Libro.h"

    Comentarios¶

    // Comentario de línea para explicaciones breves

 * Comentario de bloque para documentación de funciones públicas

    Const-Correctness¶

    // ✅ Correcto
void mostrarCatalogo() const;
bool buscar(const std::string& titulo) const;

// ❌ Evitar
void mostrarCatalogo();  // Si no modifica estado

    Smart Pointers¶

    // ✅ Preferir make_shared
auto libro = std::make_shared<Libro>("Título", "Autor");

// ❌ Evitar new directo
auto libro = std::shared_ptr<Libro>(new Libro("Título", "Autor"));

    Move Semantics¶

    // ✅ En constructores
Libro(std::string t, std::string a) : titulo(std::move(t)), autor(std::move(a)) {}

// ✅ Al retornar objetos pesados (NRVO/RVO automático en C++17+)
std::vector<Libro> obtenerLibros() { return vector; }

    📝 Commits¶

    Convención (Conventional Commits)¶

    <tipo>(<alcance>): <descripción corta>

[cuerpo opcional]

[pie opcional]

    Tipos¶

    Tipo Uso
    feat Nueva funcionalidad
    fix Corrección de bug
    docs Solo documentación
    style Formato, sin cambios funcionales
    refactor Refactorización
    test Tests
    chore Build, deps, tooling

    Ejemplos¶

    feat(biblioteca): añadir búsqueda por año de publicación
fix(prestamo): corregir devolución de libro no prestado
docs(readme): actualizar instrucciones de compilación
refactor(libro): usar move semantics en constructor
test(busqueda): añadir tests para buscarPorCategoria

    🔀 Pull Request¶

    Checklist Pre-PR¶

    • Código compila sin warnings (-Wall -Wextra -Wpedantic)
    • Tests pasan (existentes + nuevos)
    • Documentación actualizada si aplica
    • Commits siguen convención
    • Rama actualizada con main (git rebase upstream/main)
    • PR description clara

    Template PR¶

    ## Descripción
Breve explicación de los cambios.

## Tipo de Cambio
- [ ] Bug fix
- [ ] Nueva feature
- [ ] Breaking change
- [ ] Documentación

## Testing
- [ ] Tests unitarios pasan
- [ ] Tests manuales: describir pasos
- [ ] Edge cases cubiertos

## Checklist
- [ ] Código formateado (clang-format)
- [ ] Sin warnings nuevos
- [ ] Docs actualizadas

    🏷️ Versionado¶

    Usamos Semantic Versioning (SemVer):

    Versión Formato Cuándo
    Major X.0.0 Breaking changes API
    Minor 0.Y.0 Features compatibles
    Patch 0.0.Z Bug fixes

    Release Process¶

    # 1. Actualizar versión en CMakeLists.txt / docs
# 2. Actualizar CHANGELOG.md
# 3. Commit: "chore(release): v2.1.0"
# 4. Tag: git tag -a v2.1.0 -m "Release v2.1.0"
# 5. Push: git push origin main --tags
# 6. GitHub Release con notas

    🎯 Ideas para Contribuir¶

    Fáciles (Good First Issues)¶

    • Añadir validación ISBN (checksum ISBN-13)
    • Mejorar mensajes de error
    • Añadir colores ANSI opcionales (flag --color)
    • Traducir docs a inglés
    • Añadir paginación en mostrarCatalogo

    Medianas¶

    • Persistencia JSON/CSV
    • Índices hash para búsquedas O(1)
    • Sistema de usuarios simple
    • Tests unitarios con Catch2
    • CI/CD con GitHub Actions

    Avanzadas¶

    • Interfaz gráfica (Qt, Dear ImGui)
    • API REST (cpprestsdk, crow)
    • Base de datos SQLite
    • Multi-threading para búsquedas
    • Plugin system
